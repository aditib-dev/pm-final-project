Velocity: dispatcher future-state journey

RouteLogic · Strategy: reclaim operational simplicity by stripping away legacy noise and making the tool the fastest for everyday work.

Persona
The dispatcher (composite of UXR-02, 09; treated as the "Coordinator" in Snapshots 2–3)
Role
A fleet dispatcher who assigns and reassigns routes and monitors drivers in real time.
Goal
Know where every driver and stop stands, and have route changes acted on immediately.
Workaround
Runs live coordination through a WhatsApp group, "the real system" (UXR-02).

The four stages

  1. Open the fleet board
    • User action: Loads the fleet view with live stop statuses → sees the real state instantly.
    • Internal state: Trusts what the board shows → no need to cross-check WhatsApp.
    • Pain point addressed: Replaces stops showing "in progress" an hour after delivery. (UXR-09, BUG-2072)
  2. Assign routes
    • User action: Assigns routes through the optimizer in minutes → more time for live exceptions.
    • Internal state: Plans the day in one pass → confident before drivers roll out.
    • Pain point addressed: Closes the 8.2-minute vs 4.0-minute assignment gap; pilot showed +34%. (Snapshots 2–3)
  3. Reassign mid-route
    • User action: Pushes a route change → the driver is notified and acknowledges in the app.
    • Internal state: Sees the driver confirm → knows the change landed before a wrong turn.
    • Pain point addressed: Ends 8–15 minute propagation with no notification. (UXR-02, BUG-2044)
  4. Hand off the shift
    • User action: Hands over a board that matches reality → the next dispatcher starts informed.
    • Internal state: Nothing lives only in a chat thread → a clean handoff.
    • Pain point addressed: Retires WhatsApp as "the real system." (UXR-02; handoff 11.3 vs 4.5 min, Snapshot 2, link inferred)

Competitive advantages over the manual workaround

  1. One record per change: the route change and the driver's confirmation live on the route, not in a chat.
  2. No parallel channel to run: dispatchers stop maintaining a second system alongside RouteLogic.
  3. Handoff-ready history: the next shift sees every change and acknowledgment without scrolling a group chat.
Scope:
  • Stages 1 and 3 depend on real-time sync (BUG-2044, BUG-2072). If Velocity is limited to simplifying the interface, it addresses assignment time but not the dispatcher's core misery.
  • Drivers without signal (UXR-06, BUG-2050) won't receive route changes in stage 3, whatever the dispatcher does.
